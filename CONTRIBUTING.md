# Contributing

Thanks for contributing. This project is developed under the workflow in
[`CLAUDE.md`](CLAUDE.md) — read it first; it is the canonical contract for humans and AI
agents alike.

## TL;DR

1. **Design before code.** No implementation until the design is written down and any
   architectural decision is agreed (see `docs/architecture.md`).
2. **Log the task** in `TODO.md` as `TGN-<n>`. User-facing features are documented in
   `README.md`'s `## Features` section once built; backlog/ideas live in `TODO.md`.
3. **Branch** `feature/TGN-<n>-<slug>` off `dev` (there is no `main`; the flow is
   `feature/*` → `dev` → `rc` → `release`).
4. **TDD** — write the failing test first, then implement until green. No feature code
   without a test. Add the feature's test section to `docs/tests.md`.
5. **Keep docs in lockstep** in the same change (the `doc-sync` CI guard enforces this).
   Versions are auto-generated by GitVersion — never hardcode one (see `CLAUDE.md` § Versioning).
6. **Open a PR** to `dev`; merge only when CI is green. Promotion `dev` → `rc` → `release` is
   approval-gated.

## Local checks

```bash
python -m pip install -e .[dev]   # install with dev extras
ruff check .                      # lint
pytest -q                         # tests
```

Live tests that touch Telegram run **only in the sandbox** — see
[docs/sandbox-testing.md](docs/sandbox-testing.md); never point them at your real config or
account.

Optional local hook — **gitleaks** secret scan (via Docker, no local binary needed). Other
lint/scan gates run in CI, not locally.

```bash
pipx install pre-commit && pre-commit install   # then gitleaks runs on every commit
pre-commit run --all-files                       # run once over the whole repo
```

## Commit style

Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`, `ci:`). Do not add a
`Co-Authored-By` trailer.

## Security

Never commit secrets; the Telethon session is a full-access credential. Report vulnerabilities
per [`SECURITY.md`](SECURITY.md).
